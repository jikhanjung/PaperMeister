# 087 — 공통 가이드를 복사하지 않고 참조하기로

> 구현 기록 (2026-07-29). 코드 변경 없음. 바뀐 것은 **형제 프로젝트가 공유하는 규약을
> 어디서 찾느냐**이고, 답은 의도적으로 "이 저장소 안"이 아니다.

## 1. 가이드가 스스로 권하던 방식의 문제

공통 가이드 묶음은 첫머리에 이렇게 적고 있다 — *"이 디렉터리를 프로젝트 `docs/`로 복사해
계약으로 채택하라."* 이식용 표준이라면 당연히 그렇게 쓰는 문장이고, 이 저장소도 그렇게 할
참이었다.

그런데 **가이드가 작성된 다음 날 그 실패 모드가 원본에서 나왔다.**

파일 위치 가이드는 형제 프로젝트가 데이터 디렉터리를 설정 가능하게 만드는 계획을 일반화한
것이었고, 거기에 **저장소를 갈라 두라**는 권고가 들어 있었다 — 미디어는 `Documents`,
DB는 로컬 고정. 하루 뒤 상류 계획이 개정되면서 **그 절충안이 철회됐다.** 근거는 DB 없는
데이터 디렉터리는 객체 id로 이름 붙은 파일 더미라 **백업되는 절반의 복구 가치가 0**이라는
것이었다.

가이드는 그것을 알 수 없었다. 스냅샷을 일반화한 문서인데 스냅샷이 움직였기 때문이다.
**가이드는 자기가 일반화한 대상보다 먼저 낡을 수 있다.** 그리고 하필 낡은 부분이 배경 설명이
아니라 **"이렇게 하라"는 권고 문장**이었다.

여기에 "복사해서 채택하라"를 곧이곧대로 따른 프로젝트 수를 곱하면 된다. 사본 넷, 낡는 시계
넷, 그리고 **사본은 자기가 낡았다고 알려 주지 않는다.**

## 2. 대신 둔 것

`.guides/` — 공통 가이드 체크아웃을 가리키는 심볼릭 링크. `.gitignore`가 덮고 있고,
`CLAUDE.md`의 "세션 시작 시"에 적어 두어 에이전트 세션이 따로 듣지 않아도 찾는다.

명시해 둘 결과 셋:

- **갱신이 체크아웃에서 `git pull`이다.** 소유자가 하나이고 사본이 없으므로, 위의 드리프트가
  권고 사항이 아니라 **구조적으로 불가능**해진다.
- **여기에 커밋하지 않는다.** 가이드는 비공개이고 이 저장소는 공개다. 커밋하는 것은 물론
  `docs/`로 복사하는 것도 곧 공개이며, 그것은 검토했다가 접은 발행안과 같은 결과다.
- **링크는 끊어질 수 있다.** 체크아웃이 없는 머신에서 `.guides`는 아무것도 가리키지 않는다.
  이게 생각보다 중요한데, **끊어진 심볼릭 링크는 오류가 아니라 빈 디렉터리처럼 보이기**
  때문이다. 즉 장애가 "가이드에 그 내용이 없네"로 위장한다. `CLAUDE.md`에 *결론 내리기 전에
  링크부터 확인하라*고 적은 이유다.

## 3. 다른 머신에서 거는 법

체크아웃은 비공개 문서 저장소의 **부분·희소 클론**이다. `guides/`만 받고 나머지는 안 받는다.

```
git clone --filter=blob:none --sparse <devdocs>
cd devdocs && git sparse-checkout set --no-cone '/guides/'
```

그다음 형제 프로젝트 디렉터리에서:

```
ln -s ../devdocs/guides .guides
```

세 가지가 결정적이고, **셋 다 한 번씩 틀린 뒤에 알았다**:

- **`--no-cone`이 필요하다.** cone 모드는 각 상위 단계의 파일을 **항상** 포함하므로 저장소
  루트 파일이 딸려 온다. 용량 문제(수십 KB)가 아니라, `guides/`만 있는 체크아웃 옆에 놓인
  파이프라인 스크립트가 **돌릴 수 있는 것처럼 보이고**, 그 저장소의 `CLAUDE.md`가 거기서
  연 세션에 엉뚱한 지시를 붙인다는 게 문제다.
- **패턴에 앞의 `/`가 필요하다.** non-cone 패턴은 gitignore 스타일이라 `guides`는 **경로
  어디에 있든** 매칭된다 — 실제로 아카이브 안에 중첩된 무관한 `guides/` 디렉터리가 딸려
  왔다. `'/guides/'`가 루트에 앵커한다. 앵커가 없으면 **아카이브를 안 받으려고 뜬 클론이
  아카이브 일부를 받는다.**
- **심볼릭 링크 대상은 상대경로로.** 형제 프로젝트가 체크아웃과 나란히 있고, 절대경로는
  머신마다 다르다(연구소 PC와 인제스트 서버의 `projects` 위치가 다르다). 트리를 통째로
  옮겨도 살아남는 것은 덤이다. WSL에서 Windows 드라이브 위에 걸어도 양쪽 형태 다 동작하며,
  Windows는 절대경로를 junction으로, 상대경로를 디렉터리 심볼릭 링크로 본다 — 후자에는
  드라이브 문자가 박히지 않는다.

`--filter=blob:none`에는 단서가 하나 붙는다. 나머지 blob을 아예 안 받으므로 **나중에 체크아웃
범위를 넓히려면 네트워크가 필요하다.** 가이드만 읽는 머신에서는 옳은 트레이드다.

## 4. 바뀌지 않는 것

`app/`도 `desktop/`도 스크립트도 그대로다. 의존성도 빌드 단계도 늘지 않았다. 가이드는 여기서
작업하는 사람이 보는 참조 자료이지 프로그램의 입력이 아니다.

이 기록을 남기는 이유는 **`docs/guides/`가 없는 것이 누락이 아니라 결정으로 읽히게** 하기
위해서다.
