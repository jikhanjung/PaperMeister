# 092 — 한국어 매뉴얼의 백틱이 코드가 아니었던 이유

2026-08-15. 백로그에 "ko 매뉴얼에서 코드 스팬이 `<cite>`(이탤릭)로 렌더된다"로 적혀 있던 항목.
고쳐 보니 **이탤릭은 세 증상 중 가장 가벼운 것**이었고, 백로그에 적어둔 수정 방법은 틀렸다.

## 원인

Sphinx는 `msgstr`를 치환한 뒤 **reStructuredText 인라인 파서**에 넘긴다. `changelog.rst`가
myst_parser로 `CHANGELOG.md`를 include하고 있어도 마찬가지다 — 번역문은 Markdown으로 다시
읽히지 않는다. 그래서 `msgid`에서는 맞는 Markdown 습관이 `msgstr`에서는 조용히 틀린다.

## 실제 증상 (ko changelog.html, 수정 전)

영문은 `<code>` 22개 / `<cite>` 0개 / 노출된 백틱 0개. 한국어는 `<code>` 6개 / `<cite>` 11개 /
**노출된 백틱 8개**였다. 셋으로 갈린다.

1. **이탤릭** — 단일 백틱은 title-reference라서 `<cite>`가 된다. 백로그가 적어둔 증상.
2. **백슬래시가 먹힌다** — title-reference는 리터럴이 아니므로 백슬래시가 이스케이프로 처리된다.
   `%LOCALAPPDATA%\PaleoBytes\PaperMeister`가 **`%LOCALAPPDATA%PaleoBytesPaperMeister`로 렌더됐다.**
   이탤릭은 보기 싫은 정도지만 이건 **경로가 틀리게 적혀 있는 것**이다. 같은 이유로
   `--execute`는 smartquotes를 타고 `–execute`(en dash)가 됐다. 문서를 보고 따라 친 사용자는 실패한다.
3. **백틱이 그대로 보인다** — RST는 인라인 마크업 중첩을 허용하지 않는다. `**굵게 `코드` 포함**`은
   Markdown에서는 되지만 RST에서는 파싱 자체가 안 돼 백틱이 본문 글자로 출력된다.

## 백로그에 적어둔 수정 방법은 틀렸다

> "리터럴 안에서는 백슬래시가 이스케이프가 아니라서 `%LOCALAPPDATA%\\PaleoBytes`류를 같이
> `\\`→`\`로 줄여야 한다"

**PO 파일의 이스케이프 계층과 RST 계층을 섞어 본 것이다.** PO에서 `\\`는 백슬래시 하나를
뜻하므로 RST가 보는 문자열은 이미 `\` 하나다. 이중 백틱으로 바꾸면 그 하나가 리터럴로
보존되어 그냥 맞다 — 줄일 것이 없다. 실제로 아무것도 건드리지 않고 en 빌드와 바이트가 맞았다.

교훈은 방법이 아니라 절차 쪽이다. **추론 대신 양쪽을 빌드해서 세었다**(`<code>`/`<cite>`/노출 백틱).
그러지 않았으면 2번(경로 오류)은 못 봤고, 있지도 않은 백슬래시 문제를 고치느라 멀쩡한 경로를 깨뜨렸을 것이다.

## 한 일

- `changelog.po` 8개 엔트리 / 20개 스팬을 이중 백틱으로. `**굵게**` 안에 들어 있던 4개는
  중첩이 불가능하므로 **굵게를 코드 스팬 바깥으로 쪼갰다**(`**앞부분** ``코드``\ **뒷부분**`).
  결과는 en과 시각적으로 같다.
- 닫는 마크업 뒤 조사는 이스케이프 공백(`\ `)으로 붙였다. 기존 번역이 " 로 설치됩니다"처럼
  **띄어쓰기로 회피**하고 있었는데, 이제 `` ``경로``\ 로 설치됩니다 ``로 제대로 쓴다.
- `developer_guide.po`에서 같은 계열의 별개 버그 하나 — `` ``passage_fts``( ``. docutils는 닫는
  end-string 뒤에 `(`를 허용하지 않아 마크업이 안 닫히고 백틱이 샜다. `\ ` 삽입.
- 번역 누락 하나 — v0.1.0 항목의 "instead of `~/.papermeister/`"(옛 경로)가 한국어에서 통째로
  빠져 있었다. 마이그레이션을 설명하는 항목이라 채웠다. 이제 en 22 : ko 22로 코드 스팬 수가 맞는다.
- **`.mo`를 함께 커밋했다.** `docs.yml`은 `sphinx-build`만 돌리고 `sphinx-intl build`를 하지 않는다 —
  `.po`만 고쳤으면 배포본은 그대로였을 것이다.

## 재발 방지

`tests/test_manual_translations.py` — 모든 ko `.po`의 `msgstr`에 대해
(a) 단일 백틱 스팬 금지(`` `text <url>`_ `` 하이퍼링크는 허용),
(b) 인라인 리터럴 뒤에 docutils가 허용하지 않는 문자가 오는 것 금지.
수정 전 `.po`를 되돌려 넣어 **두 테스트가 실제로 red가 되는지 확인**했다.
polib를 쓰지 않는다 — sphinx-intl(문서 의존성)에 딸려 오는 것이라 테스트 환경에 없다.

## 남은 것

이 검사는 **ko `.po`만** 본다. `.rst` 원본은 이미 전부 이중 백틱이라 지금은 깨끗하지만,
누가 `.rst`에 단일 백틱을 새로 쓰면 영·한 양쪽이 같이 이탤릭이 되고 이 테스트는 잡지 못한다.
