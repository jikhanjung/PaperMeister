## 1. 논문별 진행률 (`f0dc28c`)

### 계기

사용자: *"Available generic names for trilobites 를 작업하고 있는 것 같은데 굉장히 오래 걸리네."*

로그로 확인하니 **정상이었다** — 삼엽충 속명 목록(nomenclator)이라 문서 전체가 "속명 +
명명자 + 연도" 나열이고, 참고문헌 블록이 **2,091 엔트리 / 330,012자**로 잡혔다. 같은 날
처리한 259편 중 2위가 181엔트리이니 **11배**다. 엔트리당 5.2초는 그날 평균과 같았고,
그 구간에 PARTIAL·타임아웃·5xx가 **전부 0건**이었다.

즉 **느린 게 아니라 양이 많은 것**인데, 창에서는 구분이 안 됐다. 배치 바는 논문 수만 세고
배치별 진행(`refs 551/2091`)은 **로그에만** 갔다. 정상 진행 중인 작업을 취소하게 만드는
표시다.

### 구현

`extract_references_llm(..., on_progress=None)` — `(done, total)` 콜백.

판단 두 가지:

- **첫 호출 *전*에 한 번 쏜다.** 그래야 `0/2091`이 즉시 보인다. 첫 배치가 끝난 뒤에 쏘면
  가장 불안한 30초 동안 아무것도 안 보인다.
- **스킵된 배치에서도 전진시킨다.** 그 엔트리는 어느 쪽이든 소비됐다. 안 올리면 **하필
  문제를 겪는 논문에서 바가 멈춘다** — 가장 오해를 부르는 순간에 가장 오해를 부르는 동작.

UI는 배치 바 아래 얇은 두 번째 바. **논문이 바뀌면 지운다** — 이전 논문 수치가 남으면
*진행되지 않는 진행률*로 보여 없느니만 못하다.

스레드: `BackgroundTask`에 `progress = pyqtSignal(int, int)`를 두고 **워커가 직접 emit**한다.
콜백이 위젯을 직접 건드리지 않고 큐잉된 시그널로 넘어간다. 클로저가 `task`를 늦게 바인딩하는
성질을 이용해 `on_progress=lambda d, t: task.progress.emit(d, t)`로 연결했다(`run()`은
`task` 대입 이후에 돈다).

### 검증

창을 실제로 한 사이클 돌려 라벨을 읽었다 — 시작 숨김 → `0/2091` → `599/2091 (28%)` →
논문 완료 시 숨김 → 다음 논문 `3/30 (10%)`. 콜백 계약도 테스트로 고정(첫 호출 전 보고,
뒤로 안 감, 스킵 배치도 전진).

## 2. 설정 위치 분리 (`516b5b5`)

규약과 근거는 R02에. 여기서는 **이 프로젝트에서 걸린 것**만.

### 왜 지금인가

데이터 경로를 나중에 설정 가능하게 만들려면 **선행 조건**이다 — 설정 파일이 데이터 디렉터리
안에 있으면, 데이터 위치를 알려고 설정을 읽어야 하고 설정을 읽으려고 데이터 위치를 알아야
한다(Modan2 P03이 발견한 부트스트랩 순환). 지금 떼어놓으면 그때 순환이 없다.

부수 효과가 하나 더 크다 — `preferences.json`에는 **Zotero·RunPod 평문 API 키**가 있다.
데이터 디렉터리는 59GB짜리라 언젠가 다른 드라이브·공유 위치로 갈 수 있는데, 그때 키가
따라가지 않는다.

### `QStandardPaths`를 못 쓴 이유 (Modan2와 갈리는 지점)

`paths.py`는 **`cli.py`와 `scripts/` 14개가 import**한다. 여기에 Qt를 넣으면 CLAUDE.md가
명시한 "cli.py는 PyQt6 의존 없음"이 깨지고, 헤드리스 서버에서 `refs_progress.py` 하나
돌리는 데 PyQt6가 필요해진다. → `platformdirs`(순수 파이썬, 3 OS 동일 wheel).

`appauthor`가 mac/Linux에서 무시되므로 **벤더 세그먼트는 직접 붙였다**.

### 이전을 진입점이 아니라 첫 읽기에 건 이유

스크립트와 CLI는 앱 초기화를 거치지 않는다. 진입점마다 호출을 심으면 **하나만 놓쳐도 설정
없이 조용히 도는 실행**이 생긴다(Zotero 키 없음, OCR 엔드포인트 없음). `preferences._load()`
첫 호출에 걸면 어느 경로로 들어와도 한 번 지나간다.

새 위치에 이미 있으면 **덮지 않는다**(오래된 레거시가 현재 설정을 되돌리면 조용한 회귀).
원본은 **지우지 않는다**(비용 0, 옛 빌드로 되돌려도 설정을 찾는다).

### 불변식 갱신

`test_everything_sits_under_the_data_dir`가 깨졌다 — **의도한 대로다.** "모든 경로가
DATA_DIR 아래"였는데 설정을 밖으로 뺀 게 이번 변경의 요점이다. 계약을
`test_the_library_sits_under_the_data_dir`로 바꾸고 **설정은 밖에 있어야 한다**를 명시적으로
검사한다.

## 3. 이번에 잡은 내 실수 둘

**(a) 편집 스크립트가 조용히 실패했다.** 문서 일괄 수정에 `.replace()`를 assert 없이 써서,
원문이 안 맞았는데도 "✓"를 출력했다. `faq.rst`가 안 바뀐 채 한국어에는 **옛 설명이 그대로**
남았고, gettext 재생성에서야 드러났다. → 이후 모든 편집에 `assert old in s`를 걸었다.
**출력이 성공을 뜻하지 않는 스크립트를 쓰면 검증이 무의미하다.**

**(b) 한국어 changelog가 0.1.2 이후 영어였다.** 릴리스 노트가 쌓이는 동안 카탈로그 갱신이
따라오지 않았다. 25건 번역. 남은 미번역은 버전 헤더(`[0.1.4] - 2026-07-28`)뿐이며 이건
번역 대상이 아니다.

→ **릴리스마다 `make gettext` + 번역이 체크리스트에 있어야 한다.** CHANGELOG를 고치면
ko 매뉴얼도 같이 손봐야 하는데, 그게 릴리스 절차에 없다.
