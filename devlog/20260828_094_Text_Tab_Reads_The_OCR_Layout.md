# 094 — Text 탭이 OCR을 "문서"로 읽는다: 라벨 · 캡션 · 그림

2026-08-28. 사용자가 KOFHIN 화면을 보여주며 "왼쪽 PDF, 오른쪽에 섹션 헤더가 적용된 텍스트와
figure를 같이 보여주는 것"을 Text 탭에도 원한다고 했다.

## 전제부터 틀려 있었다

Text 탭은 OCR 결과를 **마크다운으로 취급**하고 있었다. `_sanitize_ocr_markdown()`으로 다듬은 뒤
`QTextBrowser.setMarkdown()`에 넘긴다. 그런데 Chandra2가 돌려주는 건 마크다운이 아니다.

```html
<div data-bbox="107 80 653 487" data-label="Figure">
  <img alt="Geographische und geotektonische Übersicht von Marokko …"/>
</div>
```

**페이지의 레이아웃이 통째로 들어 있다** — 블록마다 그게 무엇인지(`data-label`)와 어디에
있었는지(`data-bbox`)가 붙어 있다. 마크다운 렌더러에 넘기면 그 정보가 전부 버려지고, 헤딩도
캡션도 그림도 똑같은 문단으로 평평해진다. 지금 화면이 그랬던 이유다.

라이브 캐시 9,832건 중 60건을 표본으로 세어 보니 **72%가 이 HTML 형식**이고 28%는 옛 순수
마크다운이다. 그래서 옛 경로를 지울 수는 없고, `is_structured()`로 갈라야 한다.

라벨 분포(표본 기준): `Text` 5480, `Page-Header` 1501, `Section-Header` 1143, `Image` 633,
`Page-Footer` 604, `Caption` 462, `Footnote` 280, `List-Group` 215, `Figure` 143, `Table` 119,
`Equation-Block` 68 …

## 그림은 OCR이 아니라 PDF에서 잘라 온다

`<img>`에는 **이미지 데이터가 없다.** alt 설명 하나뿐이다. 게다가 어떤 Figure 블록은 모델이
그림을 HTML로 *흉내낸* 것이 들어 있다 — `border-radius: 50%` 같은 div 뭉치라서 그대로 렌더하면
의미 없는 도형이 나온다. 쓸모 있는 건 bbox뿐이고, 그건 **페이지의 어느 사각형을 잘라내라**는
뜻이다. 그래서 pypdfium2로 페이지를 렌더해서 그 영역을 crop한다.

**좌표계는 추측하지 않고 확인했다.** bbox 최대값이 x·y 모두 900 근처에서 멈추는데, 페이지가
A4(비율 1.414)인데도 그렇다는 건 픽셀 좌표가 아니라는 뜻이다. 각 축을 독립적으로 0..1000으로
정규화한 것으로 가정하고 실제로 잘라서 **눈으로 봤다** — 모로코 지질도가 정확히 나왔다.
(처음엔 엉뚱한 텍스트가 나왔는데, `pages[].page`가 0-based인 걸 1-based로 착각한 것이었다.
좌표계 가설이 아니라 페이지 번호가 틀렸던 것이고, 이건 렌더해 보지 않았으면 몰랐다.)

## UI 스레드를 막지 않는 것이 설계의 중심이다

페이지 하나 렌더가 **약 100 ms**다(dpi와 거의 무관 — 래스터화보다 파싱이 지배적이다).
그림 있는 페이지가 열 장이면 1초, 477쪽짜리 도판 합본이면 탭이 멈춘다.

그래서:

1. **먼저 문서를 올린다.** 그림 자리는 `<img width=… height=…>`로 **미리 비워 둔다.**
2. 크기는 **페이지 자체의 비율**에서 계산한다(`pdfdoc.page_sizes()` 신설 — 래스터화 없이
   포인트 단위 크기만 읽는다). 크기를 미리 확정해야 그림이 도착할 때 **본문이 밀리지 않는다.**
3. Qt는 `<img>`에 width/height가 있으면 **그릴 때가 되어서야** `loadResource()`를 부른다.
   그래서 그림 렌더는 자연스럽게 **스크롤해서 화면에 들어올 때** 일어난다 — 477쪽 합본에서도
   본 페이지만 렌더된다. (처음엔 이걸 몰라서 "왜 요청이 0건이지?"로 한참 헤맸다. 답은
   "아직 안 그렸으니까"였다.)
4. 실제 crop은 **워커 스레드 하나**에서 순서대로. 도착하면 120 ms 디바운스로 묶어서 한 번에 교체.

측정치: 6페이지 문서 `set_pages` **146 ms**(UI 스레드), 이 중 그림 렌더는 0건.
73페이지 파싱은 **6 ms**.

## 라벨별 처리

| 라벨 | 처리 | 이유 |
|---|---|---|
| `Section-Header` | `<h2>`로 **정규화** | 모델이 h1/h4를 섞어 고른다. 그대로 두면 구조가 아니라 랜덤 폰트 크기로 읽힌다 |
| `Caption` | 작고 흐린 스타일 | 그림 바로 밑에 붙어야 캡션으로 읽힌다 |
| `Figure`/`Image`/`Diagram` | **PDF crop** | 위 참조 |
| `Table` | HTML 그대로 | 진짜 `<table>`이고 Qt가 잘 그린다. **선택 가능한 텍스트로 남는 게 crop보다 낫다** |
| `Page-Header`/`Page-Footer` | 버림 | 페이지에 속한 것이지 글에 속한 게 아니다. 매 페이지 반복되면 연속해서 읽을 수가 없다 |
| `Equation-Block` | 고정폭 | Qt는 MathML을 못 그린다. 원문을 보여주는 게 최선 |

## 남는 것

- **리사이즈 재배치는 크롭을 버리고 다시 렌더한다.** 늘려 놓고 줄이면 같은 그림을 두 번 렌더한다.
  디바운스 250 ms로 완화했지만, 원본 crop을 캐시해 두고 스케일만 바꾸는 게 더 낫다

- 옛 마크다운 캐시(28%)는 여전히 평평하게 보인다. 재OCR하면 구조가 생긴다
